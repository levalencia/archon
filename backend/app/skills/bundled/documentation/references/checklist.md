# Technical documentation checklist

## Source grounding
- Derive claims from code, tests, runtime output, or official documentation.
- Distinguish branch, main, deployed runtime, and planned behavior.

## Content
- Document contracts, trust boundaries, setup, verification, failure modes, and limitations.
- Include runnable commands but never secrets, tokens, or private environment contents.
- Prefer stable diagrams and concise tables over decorative complexity.

## Verification
- Validate links, commands, generated artifacts, and status counts.
- Update evidence and learning material from the same exact commit.
- Remove stale statements rather than layering contradictory notes.
