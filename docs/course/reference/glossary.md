## Adapter

**Also called:** concrete adapter, hexagonal adapter

**Level:** intermediate · **Category:** python-architecture

A concrete class that implements a port (Protocol) by translating between the core application's typed boundary and an external system's specific API or format.

**In Cogentrex:** OpenAI, Anthropic, Foundry, and Ollama typed adapters implement the ModelProvider Protocol. SecureToolRegistry implements ToolExecutor. Each adapter translates between Cogentrex typed values and vendor-specific APIs.

**Learn more:** [Provider Adapters Capability Parity](../concepts/provider-adapters-capability-parity.md) · [Oop Protocols Dependency Injection](../concepts/oop-protocols-dependency-injection.md) · [Ports](../../../backend/app/runtime/ports.py)

## Additional properties

**Also called:** extra properties

**Level:** beginner · **Category:** tools-policy-security

Fields present in a JSON object but not declared by its schema. Strict contracts reject them so misspellings and model-invented arguments cannot slip through.

**In Cogentrex:** SecureToolRegistry rejects undeclared tool arguments instead of silently ignoring them.

**Learn more:** [Json Schema](../concepts/json-schema.md) · [Registry](../../../backend/app/tools/registry.py)

## AES-GCM

**Also called:** authenticated encryption, AES-256-GCM

**Level:** advanced · **Category:** context-memory

An authenticated encryption mode that provides both confidentiality and integrity. Each encryption uses a fresh random nonce, and additional authenticated data binds the ciphertext to its intended context.

**In Cogentrex:** Used by ScopedEncryptedMemoryRepository with a fresh 12-byte nonce from os.urandom per encryption. AAD binds domain label, owner, project, fact ID, and key version.

**Learn more:** [Encrypted Memory](../concepts/encrypted-memory.md)

## Agent

**Also called:** AI agent, software agent

**Level:** beginner · **Category:** foundations

Software that repeatedly asks a language model what to do, may call tools, observes results, and stops under rules owned by the surrounding program. An agent is more than one model response.

**In Cogentrex:** Cogentrex is a custom typed runtime, not an agent framework. The AgentRuntime class owns the loop, budgets, policy checks, and event emission while the model acts only as an untrusted planner.

**Learn more:** [Agent Anatomy](../concepts/agent-anatomy.md) · [Readme](../modules/00-agent-anatomy/README.md) · [Engine](../../../backend/app/runtime/engine.py)

## Agent communication security

**Also called:** HMAC envelope, delegation security, envelope security

**Level:** advanced · **Category:** tools-policy-security

Cryptographic authentication of delegation metadata between parent and child agents. The envelope binds claim/evidence content, scope, budget, freshness, nonce, schema, and key version.

**In Cogentrex:** backend/app/delegation/envelope.py issues parent-signed HMAC envelopes bound to actual bounded claim/evidence content, owner/project/run scope, budget, freshness, nonce, schema, and key version with durable replay receipts.

**Learn more:** [Readme](../modules/11-bounded-delegation/README.md) · [Agent Communication Security](../concepts/agent-communication-security.md)

## Agent event

**Also called:** AgentEvent, runtime event, Discriminated event

**Level:** intermediate · **Category:** runtime

An immutable event record emitted by the runtime at a significant transition. It carries an event kind, iteration number, safe data payload, and token usage for observable execution.

**In Cogentrex:** AgentEvent is defined in runtime/events.py. The EventSink Protocol receives these events for SSE streaming, run-ledger persistence, structured logging, and observability export.

**Learn more:** [Events](../../../backend/app/runtime/events.py) · [Event Catalog](event-catalog.md)

## Agent event kind

**Also called:** AgentEventKind, event kind

**Level:** intermediate · **Category:** runtime

A string enum classifying each runtime event: RUN_STARTED, ITERATION_STARTED, MODEL_RESPONSE, TOOL_CALL_REQUESTED, POLICY_DECIDED, TOOL_CALL_COMPLETED, APPROVAL_REQUIRED, RUN_STOPPED, and many others. The closed set makes event handling exhaustive.

**In Cogentrex:** AgentEventKind is a closed StrEnum in events.py covering model, tool, policy, approval, delegation, reflection, grounding, and lifecycle transitions.

**Learn more:** [Events](../../../backend/app/runtime/events.py) · [Event Catalog](event-catalog.md)

## Agent result

**Also called:** AgentResult

**Level:** intermediate · **Category:** runtime

A frozen dataclass returned when a run finishes, containing the final content, stop reason, iteration count, recorded tool calls, accumulated token usage, optional error, and optional structured output.

**In Cogentrex:** AgentResult is defined in engine.py. It is the single return value of AgentRuntime.run(), giving callers a complete typed summary of what happened without inspecting the event stream.

**Learn more:** [Engine](../../../backend/app/runtime/engine.py) · [Typed Runtime](../concepts/typed-runtime.md)

## Agent runtime

**Also called:** runtime, AgentRuntime

**Level:** beginner · **Category:** runtime

The deterministic program that owns the agent loop, state transitions, budgets, policy checks, events, and stopping decisions. It is the authority; the model is only a planner.

**In Cogentrex:** Implemented as the AgentRuntime class in engine.py. It injects Protocol-based ports (ModelProvider, ToolExecutor, PolicyEngine, EventSink) and executes an explicit bounded state-machine loop.

## Application state

**Also called:** app.state, process state

**Level:** intermediate · **Category:** python-architecture

Process-owned shared configuration and services stored on the FastAPI application object, not user or conversation memory. Initialized during lifespan and available to all request handlers.

**In Cogentrex:** app.state holds the configured provider, DurableApprovalBroker, persistence redactor, log buffer, and telemetry exporter. Routes access these through request.app.state for request-scoped dependency construction.

## Approval

**Also called:** tool approval, human approval, durable approval, authorization

**Level:** beginner · **Category:** tools-policy-security

A human or host decision bound to an exact tool-call identity and argument hash. It is not a blanket trust grant; it is a one-use ticket that permits only the effect whose identity was shown.

**In Cogentrex:** Implemented as DurableApprovalBroker with ApprovalRepository in backend/app/security/live_approvals.py and approval_repository.py. Exact binding covers owner/run/call identity, canonical tool name, and argument SHA-256 digest.

**Learn more:** [Durable Approvals](../concepts/durable-approvals.md) · [Approvals](../../../backend/app/security/approvals.py) · [Live_Approvals](../../../backend/app/security/live_approvals.py) · [Glossary](glossary.md)

## Approval hint

**Also called:** legacy approval hint

**Level:** advanced · **Category:** tools-policy-security

A legacy annotation on a tool indicating whether it should require approval. In the current rule-based policy, unmatched tools with a legacy hint produce ASK; the hint is a fallback, not primary policy.

**In Cogentrex:** Stored as part of trusted ToolDefinition metadata. When no policy rule matches, a legacy approval hint produces ASK. Superseded by explicit policy rules when present.

**Learn more:** [Policy Engine](../concepts/policy-engine.md) · [Tool Contracts](../concepts/tool-contracts.md)

## Approval record

**Also called:** ApprovalRecord, approval receipt, Receipt

**Level:** intermediate · **Category:** tools-policy-security

A persisted database row recording an approval decision with user_id, conversation_id, run_id, status, reason, and timestamps. It intentionally stores no raw-arguments field.

**In Cogentrex:** ApprovalRecord in backend/app/security/approval_repository.py. Terminal states are APPROVED, DENIED, EXPIRED, or CANCELLED. Conditional SQL update ensures only one transition wins from PENDING.

**Learn more:** [Durable Approvals](../concepts/durable-approvals.md)

## Approval TTL

**Also called:** approval time-to-live, approval expiry, TTL

**Level:** intermediate · **Category:** tools-policy-security

The time-to-live after which a pending approval automatically becomes expired. This bounds human decision latency so the runtime does not wait indefinitely.

**In Cogentrex:** ApprovalRepository.reserve inserts the receipt with a positive TTL. expire_due transitions stale pending approvals. The stop reason approval_timeout fires if the deadline passes.

**Learn more:** [Durable Approvals](../concepts/durable-approvals.md) · [Stop Reasons](stop-reasons.md)

## Arguments hash

**Also called:** canonical arguments hash

**Level:** advanced · **Category:** runtime

A deterministic hash of the canonicalized tool call arguments used to bind an approval to an exact invocation. If arguments change, the hash changes and the approval no longer matches.

**In Cogentrex:** canonical_arguments_hash in security/policy.py produces a stable hash from canonical_arguments_snapshot. This ensures approvals are exact-bound and cannot be reused for different arguments.

**Learn more:** [Policy](../../../backend/app/security/policy.py) · [Durable Approvals](../concepts/durable-approvals.md)

## Artifact

**Also called:** output artifact, stored artifact

**Level:** intermediate · **Category:** context-memory

A named output produced during a run, such as generated code or a document. Artifacts are persisted with redaction and subject to the same data boundary controls as other stored content.

**In Cogentrex:** backend/app/services/artifacts.py manages artifact storage. Artifacts pass through PersistenceRedactor before storage and are subject to security resource tests.

**Learn more:** [Multimodal And Artifacts](../concepts/multimodal-and-artifacts.md)

## Artifact Persistence

**Also called:** artifact storage

**Level:** intermediate · **Category:** delivery-media

Storing generated artifacts (code, documents, media) with owner scoping, security scanning, and authenticated access controls.

**In Cogentrex:** Cogentrex persists artifacts with owner scoping and security controls; no durable attachment backend or public hosting is claimed.

## Async/await

**Also called:** async, await, cooperative concurrency, asyncio

**Level:** beginner · **Category:** python-architecture

Python's cooperative concurrency model where async functions yield control at await points while waiting for I/O. It does not automatically make CPU work faster; it enables efficient waiting.

**In Cogentrex:** All provider calls, tool executions, approval waits, and event emissions are async. The runtime uses asyncio for cooperative I/O concurrency, guarded by deadlines to prevent indefinite waits.

**Learn more:** [Async Python](../concepts/async-python.md) · [Readme](../modules/01-python-architecture/README.md) · [Engine](../../../backend/app/runtime/engine.py)

## At-least-once delivery

**Also called:** At-least-once

**Level:** intermediate · **Category:** tools-policy-security

A delivery strategy that retries to reduce lost work but may deliver the same operation more than once. Receivers therefore need idempotency.

**In Cogentrex:** Cogentrex treats retries and duplicate requests as possible and uses stable identities plus effect-ledger checks to contain them.

**Learn more:** [Idempotency](../concepts/idempotency.md) · [Effect_Ledger](../../../backend/app/runtime/effect_ledger.py)

## Atomic uniqueness

**Level:** intermediate · **Category:** tools-policy-security

A database constraint or conditional write that lets concurrent attempts choose one winner without a check-then-write race.

**In Cogentrex:** The effect ledger relies on database-enforced uniqueness rather than process-local memory.

**Learn more:** [Idempotency](../concepts/idempotency.md) · [Effect_Ledger](../../../backend/app/runtime/effect_ledger.py)

## Authorization request

## Autonomous Unapproved Production Optimization

**Level:** advanced · **Category:** delivery-media

## Background job

**Also called:** durable job, task queue job

**Level:** intermediate · **Category:** context-memory

An owner/project-scoped durable task with atomic claim, lease fencing, heartbeat, retry/dead-letter, and cancellation. Execution is at-least-once, not exactly-once.

**In Cogentrex:** backend/app/services/task_queue.py and backend/app/workers/jobs.py implement SQL-based durable jobs. Non-idempotent external-effect job kinds are prohibited because in-process coroutines cannot be forcibly killed.

## Batch policy evaluation

**Also called:** pre-validation, batch pre-validate

**Level:** advanced · **Category:** runtime

The runtime evaluates policy for all tool calls in a model response as a batch before executing any of them. This prevents partial execution followed by denial.

**In Cogentrex:** AgentRuntime pre-validates the complete call batch against policy before executing any tool. If any call is denied, the entire batch fails and no tools execute in that iteration.

## Cancellation

## Tool definition

**Also called:** ToolDefinition, tool schema, provider definition

The provider-facing description of a tool: its name, description, and input schema. This is deliberately less than the full trusted registration metadata to prevent the model from rewriting permissions or risk classes.

A Protocol that defines two methods: execute(call) to run a tool call and return a result mapping, and definitions() to list available tool definitions. Separates tool capability from runtime control.

## Tool handler

**Also called:** handler function, capability handler, Handler

**Level:** intermediate · **Category:** tools-policy-security

The function that performs the actual capability when a tool call is authorized and validated. It runs within a bounded timeout enforced by the registry.

## Tool input schema

**Also called:** input schema, argument schema

**Level:** intermediate · **Category:** tools-policy-security

A JSON Schema subset describing the allowed shape and types of a tool's arguments. Validated at registration time and again at every call to reject malformed arguments before execution.

**In Cogentrex:** Cogentrex uses a deliberately small validated subset: object/property/type/enum. Unknown schema keywords are rejected fail-closed. Recursive or remote full-spec JSON Schema is intentionally outside the tool-contract boundary.
