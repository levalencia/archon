# AIAMastery Days 1–30: concept coverage

> **Reviewed revision:** `6e3e13f`
> **Scope:** Luis-authored concept/status synthesis; no paid lesson prose is reproduced.
> **Status vocabulary:** `implemented` means meaningful behavior is wired, tested, and evidenced within its stated boundary; `partial` names an incomplete boundary; `not-implemented` means no meaningful implementation; `deferred` means deliberately out of scope without a delivery promise.

## Omitted-concept status summary

The added canonical pages separate nearby ideas that the original 47-page set could otherwise overclaim:

- **Implemented within a bounded local contract:** PII-before-persistence, optional Docker-only execution isolation, durable monetary budgets, validated structured output/cache accounting, live Foundry embeddings, bounded faithfulness verification, shared context/deadline controls, and durable at-most-once effects.
- **No unresolved `Partial` rows:** every course day is either implemented within a named boundary or explicitly deferred where it requires an unapproved distributed/cloud/workspace target.
- **Implemented with explicit governance boundaries:** redacted run export/share, bounded reflection, and human-approved drift recommendations.
- **Deferred:** autonomous production mutation, distributed agent networks, high-throughput serving, fine-tuning/vertical adaptation, scheduled autonomy, and public deployment.

A stub, manifest, unit-tested helper, or adjacent capability is not promoted to `implemented`. In particular: tool-error feedback is not generic self-reflection; a local verifier is not a distributed network; RAG/skills are not fine-tuning; an HPA manifest is not throughput evidence; persistence redaction is not a safe sharing workflow; and local Compose is not public deployment.
